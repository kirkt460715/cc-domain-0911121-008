# 动态凭据页面与网页证据采集

## 演练来源

`python portal/server.py --port 8787` 启动来源。页面异步加载正文，`#record[data-ready=true]` 是业务就绪标志，`data-revision` 是页面内容版本；按钮可以改变版本或发起导航，`/missing-image` 保持失败以展示资源清单中的失败项。页面文本为本地合成记录。

故障开关（均为查询参数，仅用于演练）：

- `?drift=revision&token=<标识>`：同一 token 的第二次内容轮询返回更高版本，模拟就绪后的一次性版本改变，触发整组重试；
- `?drift=revision-always`：每次内容轮询都改变版本，持续漂移导致采集在最大尝试次数后整组失败；
- `?drift=navigate-always`：页面就绪前持续发起导航，模拟无法稳定的跳转；
- 页面每 300 毫秒后台轮询一次 `/content`，模拟延迟渲染与运行期版本切换；
- `http://127.0.0.1:9/tracker.gif` 是批准范围外的跟踪像素，用于验证逐请求策略拦截，本机无服务监听。

## 采集证据组

浏览器入口以一个 URL 和操作员预先批准的 origin/路径集合开始，每个导航与资源请求都重新检查策略；非 HTTP(S) 协议、越界 origin、越界路径（含点段归一化后的路径穿越）一律拒绝，浏览器侧通过路由拦截实际阻断。浏览器使用一次性上下文，不携带持久配置；cookies、`Set-Cookie`、`Authorization`、`Proxy-Authorization` 及凭据值不进入证据记录，记录校验会直接拒绝这类字段。

采集仅在业务就绪标志出现、且 URL 与页面版本在静默窗口内保持不变后进行。截图与最终 DOM 在同一次稳定状态下背靠背采集，采集后再次复核 URL、就绪标志和版本；期间发生导航或版本改变则整次尝试作废并整组重试，超过 `max_attempts` 报告失败，绝不拼接两次访问。

每个证据组包含三件套，统一挂在 `captures/<capture_id>/` 下：

- `screenshot.png`：该次稳定状态截图；
- `dom.html`：同一稳定状态的最终 DOM；
- `capture.json`：信封式清单，含目标地址、最终地址、页面时间、采集时间、稳定版本、尝试链、导航链、资源清单（请求地址、最终地址、方法、状态、媒体类型、字节数与 SHA-256 摘要，或失败/拦截原因），以及截图与 DOM 的摘要和策略指纹。

清单只保存元数据与对象摘要，不保存响应体、cookie 或凭据。挂载在单个案件事务内完成：浏览器失败或采集期间案件被封存（不再是 draft）时，任务记录为 `failed` 并保留原因，不写入任何半组附件；同一采集的重复确认返回同一证据组，不增加第二组附件。

## 演练与核对

`python demo_support/capture_drill.py` 运行全部本地浏览器场景：稳定采集挂载、一次性漂移重试、持续漂移整组失败、采集期间封存的竞态失败、重复确认幂等、封存后摘要与关联重新核对、策略层与浏览器侧拦截。所有 HTTP 通信只走容器内回环地址。封存后的核对只比较截图、DOM、清单的摘要及其与封存清单条目、监管链事件的关联，不做 OCR，也不自动判断页面真伪。

案件配置沿用 Sealvault CLI 与 `fixtures/sealing.json`；来源页面不写入证据库。
